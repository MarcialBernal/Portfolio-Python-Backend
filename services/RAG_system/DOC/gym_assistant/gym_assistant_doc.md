## 2. Assistant Layer

### File

```text
assistant.py
```

### `GymAssistant`

The `GymAssistant` class encapsulates the OpenAI client, system prompt, tool definitions, and conversation execution logic.

The OpenAI client is initialized with the `OPENAI_API_KEY` environment variable:

```python
self.client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))
```

The assistant uses the `gpt-4o-mini` model.

### System Prompt

The system prompt instructs the model to:

- respond in the user's language
- collect user information in a fixed order
- request only one missing field at a time
- search for an existing user after receiving name and age
- create a user when no matching record exists
- generate a workout plan after the required database operation

The expected collection order is:

```text
name
age
weight
height
training_days
training_hours
goal
experience
```

### Tools

The assistant defines two OpenAI function tools:

#### `get_user_by_name_and_age`

Searches for a user using:

```text
name
age
```

#### `add_user`

Creates a user using:

```text
name
age
weight
height
training_days
training_hours
goal
experience
```

### `run(conversation)`

The `run()` method:

1. Adds the system prompt to the conversation.
2. Sends the messages and tools to OpenAI.
3. Checks whether the response contains a tool call.
4. Parses the tool arguments.
5. Opens a SQLAlchemy database session.
6. Executes the requested CRUD operation.
7. Adds the database result to the conversation.
8. Sends the updated conversation to OpenAI.
9. Returns the assistant's final message.

If OpenAI does not request a tool, the method returns the original response content.

## 3. Database Layer

### File

```text
database.py
```

The service uses SQLite with SQLAlchemy.

The database path is generated from the module directory:

```text
services/gym_assistant/users.db
```

The main database objects are:

- `engine`
- `SessionLocal`
- `Base`
- `get_db()`

### `get_db()`

Creates a database session for FastAPI dependencies and closes it after the request is completed.

### File

database_init.py

Base.metadata.create_all(bind=engine)

## 5. ORM Model

### File

```text
models.py
```

### `User`

The `User` SQLAlchemy model maps to the `users` table.

Fields:

| Field | Type | Required |
|---|---|---|
| `id` | Integer | Primary key |
| `name` | String | Yes |
| `age` | Integer | Yes |
| `weight` | Float | Yes |
| `height` | Float | Yes |
| `training_days` | Integer | Yes |
| `training_hours` | Float | Yes |
| `goal` | String | Yes |
| `experience` | String | No |
| `created_at` | DateTime | Generated by database |

The `name` field is indexed.

## 7. CRUD Layer

### File

```text
crud.py
```

### `get_user()`

Retrieves users whose name matches the provided value.

If no users are found, it raises an HTTP 404 exception.

### `get_user_by_name_and_age()`

Searches for the first user whose name and age match the provided values.

The name comparison uses a case-insensitive SQL `LIKE` operation.

### `get_users()`

Returns all users stored in the database.

### `create_user()`

Creates a SQLAlchemy user object, commits it, refreshes it, and returns the persisted record.

### `update_user()`

Finds a user by ID and updates only the fields provided in the request.

### `delete_user()`

Deletes a user by ID and returns a confirmation message.

## 8. API Routes

### File

```text
routers/routes.py
```

### User Endpoints

#### Get users by name

```http
GET /users/{user_name}
```

#### Get user by name and age

```http
GET /users/{user_name}/{age}
```

#### Get all users

```http
GET /users
```

#### Create user

```http
POST /users
```

#### Update user

```http
PUT /users/{user_id}
```

#### Delete user

```http
DELETE /users/{user_id}
```

### Assistant Endpoint

```http
POST /assistant
```

Expected request structure:

```json
{
  "messages": [
    {
      "role": "user",
      "content": "Hello"
    }
  ]
}
```

The route sends the `messages` value to:

```python
assistant.run(messages)
```

The response structure is:

```json
{
  "reply": "Assistant response"
}
```

## 9. Request Flow

### User Management

```text
HTTP request
    ↓
FastAPI route
    ↓
Database dependency
    ↓
CRUD function
    ↓
SQLAlchemy session
    ↓
SQLite database
    ↓
Validated response
```

### Assistant Conversation

```text
HTTP request
    ↓
/assistant route
    ↓
GymAssistant.run()
    ↓
OpenAI Chat Completions API
    ↓
Optional tool call
    ↓
CRUD operation
    ↓
Database result
    ↓
Second OpenAI request
    ↓
Assistant response
```

## 10. Environment Variables

The assistant requires:

```text
OPENAI_API_KEY
```

The key is loaded using `python-dotenv` and read through `os.getenv()`.

## 11. Current Implementation Notes

The assistant uses OpenAI tool calls to decide when to query or modify user data. The database operations themselves are implemented in the CRUD layer, while the conversational behavior is defined in the system prompt.
